# Быки и коровы: устройство решения

Игровая логика лежит в `src/core/` и не зависит от DOM. Интерфейс в `src/ui/` только вызывает функции ядра. Ниже описаны структуры данных и алгоритмы, их сложность и принципы чистого кода с привязкой к файлам.

Обозначения в оценках сложности:

- `n` - длина секрета, от 2 до 6;
- `b` - основание системы счисления: 2, 8, 10 или 16;
- `h` - число ходов в партии.

## 1. Структуры данных и алгоритмы

### Секрет и вариант игрока: строка

Секрет и вариант игрока хранятся строками из цифр в нижнем регистре, например `"0a3f"`.

Почему строка, а не число:

- число потеряло бы ведущий ноль: `0123` превратилось бы в `123`;
- шестнадцатеричные цифры `a`-`f` числом не записать;
- строка неизменяема и сравнивается через `===`.

Для подсчетов строка превращается в массив цифр функцией `toDigits` (`src/core/guess.ts`). Она же приводит цифры к нижнему регистру, поэтому `A` и `a` считаются одной цифрой.

### Состояние игры: неизменяемый объект

```ts
interface GameState {
  readonly settings: GameSettings; // длина и основание
  readonly secret: string;
  readonly history: readonly Attempt[];
  readonly status: 'playing' | 'won';
  readonly startedAt: number;
  readonly finishedAt: number | null;
}
```

Состояние никогда не меняется на месте. `submitGuess` (`src/core/game.ts`) возвращает новый объект: `{ ...state, history: [...state.history, attempt] }`. Тесты замораживают состояние через `Object.freeze`, поэтому любая мутация в реализации вызвала бы `TypeError` и тест упал бы.

Время старта и конца приходит параметром `now`: функции ядра сами не вызывают `Date.now()`. Так `createGame` и `submitGuess` остаются чистыми и проверяются без подмены часов.

На ошибочный ход `submitGuess` не бросает исключение. Она возвращает `{ state, error }`, где `error` равен `'invalid'`, `'duplicate'` или `'finished'`, а `state` остается прежним объектом. Неверный ввод в игре - обычное дело, и обработать его проще как результат функции. Исключение бросает только `generateSecret`, если длина больше основания: такую комбинацию интерфейс выбрать не дает.

### История ходов: массив только на добавление

История хранится массивом `Attempt` (`{ guess, bulls, cows }`). Массив подходит, потому что:

- порядок важен: номер хода равен индексу плюс один;
- записи только добавляются, старые не меняются и не удаляются;
- длина массива и есть число попыток для рекордов.

Повтор варианта проверяет `history.some(...)`. Варианты в истории уже приведены к нижнему регистру, поэтому `CD` после `cd` тоже считается повтором.

### Рекорды: один плоский массив

Рекорды всех настроек лежат в одном массиве `GameRecord` (`src/core/records.ts`). Каждая запись хранит свою длину и основание, а интерфейс показывает отдельную таблицу для выбранной комбинации.

- `compareRecords` сортирует по числу ходов, при равенстве по времени.
- `getRecordsFor` отбирает записи одной комбинации и сортирует их.
- `addRecord` оставляет 10 лучших записей этой комбинации (`RECORDS_LIMIT`) и не трогает остальные.
- `parseRecords` читает данные из `localStorage` с проверкой: на битом JSON возвращает пустой список, а записи с неверными полями отбрасывает.

### Вспомогательные структуры

- **`Set` в `createDigitValidator`** (`src/core/digits.ts`). Допустимые цифры системы собираются в `Set` один раз, дальше проверка символа занимает `O(1)`. Функция каррированная: `createDigitValidator(base)` возвращает предикат `(char) => boolean`. Предикат используется в двух местах: в `isValidGuess` (`src/core/guess.ts`) и при вводе в интерфейсе (`src/ui/board-view.ts`, обработчики `beforeinput` и `input`).
- **`Map` в `memoize`** (`src/core/memoize.ts`). Ключ - `JSON.stringify(args)`, поэтому вызовы `(1, 23)` и `(12, 3)` не путаются. Значение обернуто в `{ value }`, чтобы кешировались и результаты `0`, `false`, `''`.

### Алгоритм `evaluateGuess`

```ts
const bulls = guessDigits.filter((digit, index) => digit === secretDigits[index]).length;
const matches = guessDigits.filter((digit) => secretDigits.includes(digit)).length;
return { bulls, cows: matches - bulls };
```

1. Обе строки превращаются в массивы цифр в нижнем регистре.
2. Быки: сколько цифр варианта совпадает с цифрой секрета на той же позиции.
3. Совпадения: сколько цифр варианта есть в секрете на любой позиции.
4. Коровы: совпадения минус быки.

Шаг 4 корректен, потому что цифры в секрете и в варианте не повторяются. Каждая цифра варианта совпадает с секретом не больше одного раза, и это совпадение либо на своем месте (бык), либо на чужом (корова).

Пример: секрет `4702`, вариант `4079`. Бык один (`4`), совпадений три (`4`, `0`, `7`), значит коров две.

### Алгоритм `countPossibleSecrets`

Число секретов равно числу размещений без повторений: `P(b, n) = b · (b - 1) · ... · (b - n + 1)`. Ведущий ноль разрешен, поэтому ничего вычитать не нужно.

Функция считает его рекурсивно:

```ts
countPossibleSecrets(length, base) =
  length <= 0 ? 1 : base * countPossibleSecrets(length - 1, base - 1);
```

- База рекурсии: секрет нулевой длины ровно один, пустая строка.
- Шаг: на первую позицию подходит любая из `b` цифр, а оставшиеся `n - 1` позиций заполняются из `b - 1` цифр.
- Если длина больше основания, в произведение попадает множитель `0`, и функция возвращает `0`.

Функция обернута в `memoize`. Рекурсивный вызов идет через уже мемоизированную ссылку `countPossibleSecrets`, поэтому в кеш попадают и промежуточные шаги. Пример: `countPossibleSecrets(4, 10) = 10 · 9 · 8 · 7 = 5040`.

## 2. Сложность

| Функция                | Время                                          | Память     |
| ---------------------- | ---------------------------------------------- | ---------- |
| `generateSecret`       | `O(n · b)`                                     | `O(n · b)` |
| `evaluateGuess`        | `O(n²)`                                        | `O(n)`     |
| `isValidGuess`         | `O(n + b)`                                     | `O(n + b)` |
| `countPossibleSecrets` | `O(n)` при первом вызове, `O(1)` при повторном | `O(n)`     |

**`generateSecret`.** `getDigits` строит алфавит из `b` цифр за `O(b)`. Затем `pickUniqueDigits` делает `n` рекурсивных шагов. На каждом шаге `filter` строит новый пул без выбранной цифры, это до `b` операций. Сборка результата через spread добавляет `O(n)` на шаг, но при `n ≤ b` итог не меняет: `O(n · b)`. По памяти: глубина рекурсии `n`, и каждый уровень держит свой пул размером до `b`, отсюда `O(n · b)`. При `n ≤ 6` и `b ≤ 16` это меньше сотни операций.

**`evaluateGuess`.** Подсчет быков - один проход, `O(n)`. Подсчет совпадений вызывает `includes` для каждой из `n` цифр, а `includes` сам проходит до `n` элементов: `O(n²)`. Через `Set` можно получить `O(n)`, но при `n ≤ 6` это не больше 36 сравнений, и простой вариант читается лучше.

**`isValidGuess`.** `createDigitValidator(base)` собирает `Set` из `b` цифр за `O(b)`. `toDigits`, проверка `every` и проверка повторов через `Set` проходят по `n` цифрам за `O(n)` каждая. Итого `O(n + b)`.

**`countPossibleSecrets`.** При первом вызове с аргументами `(n, b)` функция выполняется `n + 1` раз, для длин от `n` до `0`. Каждый раз это `O(1)`: умножение, ключ из двух чисел и обращение к `Map`. Итого `O(n)` по времени и `O(n)` по глубине стека. Повторный вызов с теми же аргументами, как и вызов для любого промежуточного шага, берет готовое значение из `Map` за `O(1)`. Форма настроек вызывает функцию при каждой перерисовке, поэтому кеш окупается.

## 3. Принципы чистого кода

### Имена понятны без комментариев

- `isValidGuess`, `isLengthAvailable`, `hasBeenGuessed`, `hasUniqueItems` - предикаты с префиксами `is` и `has`, они читаются как вопрос.
- `createDigitValidator` (`src/core/digits.ts`): по имени видно, что это фабрика, которая создает проверку цифры.
- `fitLengthToBase` (`src/core/settings.ts`) подгоняет длину под основание: после выбора bin длина 4 становится 2.

### Одна функция - одна задача

`submitGuess` (`src/core/game.ts`) координирует ход и передает работу трем функциям:

- `normalizeGuess` приводит вариант к нижнему регистру;
- `getGuessError` решает, можно ли принять ход;
- `evaluateGuess` считает быков и коров.

В интерфейсе то же разделение: `renderStatusBar`, `renderGuessForm`, `renderDraft`, `renderHistory` и `renderWin` (`src/ui/board-view.ts`) отвечают каждая за свой блок экрана.

### Чистое ядро, побочные эффекты в интерфейсе

- Источник случайности и время приходят параметрами: `generateSecret(length, base, random = Math.random)`, `submitGuess(state, guess, now)`. В тестах передается детерминированный `random`, и результат известен заранее.
- Работа с `localStorage` вынесена в `src/ui/storage.ts` и `src/ui/theme.ts`. В ядре остались чистые `parseRecords` и `serializeRecords`.
- ESLint закрепляет границу (`eslint.config.js`): в `src/core/` запрещены классы, циклы `for` и `while`, изменение аргументов и обращения к `window`, `document`, `localStorage`.

### Ранний выход вместо вложенных условий

`getGuessError` (`src/core/game.ts`) проверяет условия по очереди и сразу возвращает ответ: игра окончена, вариант недопустим, вариант уже был. Вложенных `if` нет.

### Комментарии объясняют "почему"

Комментариев мало, и в основном они объясняют решения, которые не видны из кода:

- `src/core/secret.ts`: зачем рекурсия идет через мемоизированную ссылку;
- `src/core/settings.ts`: почему длина не может быть больше основания;
- `src/ui/board-view.ts`: почему черновик меняется без перерисовки (иначе пропадает анимация зачеркивания).

### Константы вместо магических чисел

- `RECORDS_LIMIT = 10` (`src/core/records.ts`) - размер таблицы рекордов.
- `MIN_LENGTH` и `MAX_LENGTH` (`src/core/settings.ts`) - границы длины, из них строится `LENGTH_OPTIONS`.
- `HISTORY_PREVIEW = 8` (`src/ui/board-view.ts`) - сколько ходов видно на телефоне до кнопки "Показать ранние ходы".

### DRY: одно правило в одном месте

Правило "цифры сравниваются без учета регистра" записано один раз, в `normalizeDigit` (`src/core/digits.ts`). Им пользуются `createDigitValidator` и `toDigits`, а через `toDigits` - `evaluateGuess`, `isValidGuess`, `submitGuess` и `sanitizeGuessInput`. Если правило поменяется, править нужно одно место.

### KISS и YAGNI

- `evaluateGuess` использует `includes`, а не `Set`: при длине до 6 цифр выигрыша нет, а код короче (см. раздел 2).
- Основание - тип `Base = 2 | 8 | 10 | 16`, а не любое число от 2 до 36. Игре нужны четыре системы, и TypeScript не даст передать пятую.
- Мемоизация написана один раз как общая функция `memoize`, но применена только там, где ее требует задание: в `countPossibleSecrets`.
